# План прогона на настоящей модели

Этот документ описывает, как проверять продукт на настоящей модели: какими командами и на что смотреть в отчётах. Цель прогона: найти слабые места до сдачи, а не подтвердить, что всё хорошо. Первый прогон сделан в ночь на 27.11, его итоги ниже.

## Что показал первый прогон

Модель: Claude Haiku 5.5 через ProxyAPI. Три полных прогона, между ними исправления.

| | Первый прогон | Третий прогон |
|---|---|---|
| Контрольные вопросы | 20 из 21 | 21 из 21 |
| Правила кода в сценариях | 26 из 46 | без ошибок |
| Качество в сценариях | 25 из 25 | 23 из 25, одна из двух неудач относилась к языку хинди, выбор языков после этого убран |
| Ответов, где модель исправляла себя лишним вызовом | 13 из 29 | 0 из 28 |
| Стоимость сценария | 2,71 ₽ | 1,89 ₽ |
| Самый долгий ход | 84 с | 44 с |

Что нашлось и исправлено:

1. **Карточка вердикта пропадала.** Если результат проверки уже был сохранён, модель не вызывала диагностику повторно и механик получал обычный текст без карточки, приоритета и кнопки заявки. Это и дало 20 ошибок в правилах. Теперь на просьбу показать результат инструмент вызывается всегда.
2. **Проверка чисел придиралась к ссылкам.** Номера страниц, рисунков и пунктов, даты, обозначения документов и крепежа считались «нормативом без источника». Модель тратила вызов на исправление почти в каждом втором ответе.
3. **Цитаты из таблиц не проходили сверку.** Из-за этого потерялся ответ на простой вопрос о порядке работы цилиндров. Теперь принимается ячейка таблицы с числом и строка таблицы, ячейки которой PDF отдаёт в другом порядке. Фраза, собранная из слов с разных концов страницы, по-прежнему не проходит.
4. **Ответы были слишком длинными.** До 4 тысяч знаков на вердикт. В инструкции заданы пределы, код обрезает списки.
5. **Противоречие в тексте.** Модель писала «источники не расходятся» по теме с подтверждённым расхождением. Теперь поиск сообщает модели о нём заранее.

Что осталось слабым:

- Перед показом надо очистить данные стенда: после прогонов по демонстрационной проверке S-0043 уже есть заявки, агент предупреждает о них в черновике.

Данные третьего прогона для шаблона расчёта, цены ProxyAPI с НДС 5%: ввод 30 ₽, вывод 150 ₽, чтение кэша 3 ₽, запись в кэш 37,5 ₽ за 1 млн токенов.

| Шаг | Вызовов на сценарий | Вход на вызов | Выход на вызов | Из кэша на вызов | ₽ на сценарий |
|---|---|---|---|---|---|
| Выбор инструмента и поиск | 2,06 | 8 372 | 265 | 3 609 | 0,75 |
| Генерация ответа | 1,65 | 5 380 | 2 813 | 10 769 | 1,08 |
| Формирование заявки | 0,06 | 8 641 | 4 513 | 12 037 | 0,06 |
| Повтор после проверки ссылок | 0 | | | | 0 |

Итого 1,89 ₽ на сценарий с НДС, 1,80 ₽ без НДС. Отдельный вопрос механика стоит около 0,94 ₽. Доля заявки мала, потому что в прогоне заявка создаётся в одном сценарии из семнадцати: для сценария «отклонение с заявкой» полная стоимость была 3,7 ₽.

## Прогон 27.11 вечером, после слияния журнала, входа и API

Тот же Claude Haiku 5.5 через ProxyAPI, стенд в Docker со включённым входом (скрипты ходят по служебному ключу `INTEGRATION_API_KEY`).

- Контрольные вопросы: 21 из 21. Скрипт насчитал 20: в вопросе 236-05 агент сослался на РК стр. 254, п. 5.10.4 (те же 120–150 Н·м для гаек крепления стоек коромысел), а в разметке набора этой страницы не было. Страница добавлена в набор. Прогон стоил 21,25 ₽.
- Сценарии защиты: правила кода 47 из 47, качество модели 21 из 21, 27 ходов за 8 минут, самый долгий ход 50 с.
- Новые проверки сценариев: посторонний текст в описании ML отмечен в ходе разбора и в результате проверки, механику не показан; в расхождении есть «Как поступить».
- Быстрая проверка стенда без модели (`eval.smoke`): 29 из 29.

Прогон 28.11 ночью, после правил коротких ответов на уточнения:

- Сценарии защиты: правила кода 47 из 47, качество 21 из 21. До этого одно ослабление правила про ссылки пропустило ответ без страниц на вопрос С2 («можно ли своим ходом»); правило возвращено, прогон повторён.
- Контрольные вопросы: 19 из 21 по разметке. Оба расхождения — страницы, которых не было в наборе, нормативы на них стоят дословно: прогиб ремня 10–15 мм при 40–45 Н (РК стр. 259, п. 5.15.2), момент затяжки болтов осей коромысел 120–150 Н·м (РК стр. 270). Страницы добавлены в набор, по нему 21 из 21. 20,45 ₽.
- Уточнение «что в итоге делать» после результата диагностики на трёх машинах (О263СН47, Т792НО98, А427МА78): короткий ответ по порядку со ссылками на шаги выше, без нового поиска, без повтора шагов и без ложных расхождений, 0,61–0,81 ₽ за ответ.

Найдено и исправлено: раздел отчёта «Для шаблона расчёта» был пустым. Время в базе пишется в поясе контейнера (UTC), скрипт передаёт московское, строки сравнивались неверно; теперь сравнение через `datetime()` SQLite.

## Шаги

1. Вписать в `.env` ключ и адрес. Для ProxyAPI:

```bash
LLM_PROVIDER=anthropic
ANTHROPIC_BASE_URL=https://api.proxyapi.ru
ANTHROPIC_API_KEY=ключ_ProxyAPI
LLM_MODEL=anthropic/claude-opus-5-5
PRICE_CURRENCY=RUB
PRICE_INPUT_PER_MTOK=цена_ввода_с_сайта
PRICE_OUTPUT_PER_MTOK=цена_вывода_с_сайта
PRICE_CACHE_READ_PER_MTOK=цена_чтения_кэша_с_сайта
```

2. Перезапустить сервер:

```bash
docker compose up -d --build backend
```

3. Проверить ключ и то, какие возможности принимает шлюз. Скрипт сам подскажет, что выключить в `.env`:

```bash
docker compose exec backend uv run --no-dev python -m eval.preflight
```

4. Прогнать сценарии. Отчёт сохраняется в `data/eval`:

```bash
docker compose exec backend uv run --no-dev python -m eval.run_scenarios
```

5. Прогнать 21 контрольный вопрос:

```bash
docker compose exec backend uv run --no-dev python -m eval.run_eval ask
```

6. Для сравнения с другой моделью поменять настройки модели в `.env` и повторить шаги 2–5. Результаты внести в [model-comparison.md](model-comparison.md).

Прогон очищает чат по машинам из сценариев и создаёт одну заявку в заглушке ТОиР. Ключ `--no-ticket` у прогона сценариев отключает отправку заявки.

## Как читать отчёт сценариев

- **Ошибки в правилах.** Их быть не должно при любой модели. Каждая такая строка означает ошибку в коде, чинить до сдачи.
- **Слабые места модели.** Это список для доработки инструкции агента и поиска. Если пункт не лечится инструкцией, он попадает в честный раздел «Что не сделано».
- **Расход по сценариям и таблица для шаблона.** Из них заполняется расчёт стоимости.

## Где мы ждём слабые места

Это предположения, прогон должен их подтвердить или снять.

1. **Новый шлюз или модель.** Первый запрос может упасть на параметре, который сервис не принимает. Для этого сделаны предполётная проверка и выключатели в `.env`. ProxyAPI принял все возможности слоя.
2. **Дословность цитат.** Если модель пересказывает страницу вместо копирования, код отбросит пункт и механик увидит «подтвердить не удалось». Признак: много отказов на вопросах, где ответ в руководстве есть.
3. **Не то число с правильной страницы.** Код проверяет, что число стоит на странице, но не что оно отвечает на вопрос. На слабой модели это случалось. Признак: в прогоне вопросов «нет ожидаемых чисел» при верной странице.
4. **Поиск только по словам.** Синонимы и разговорные формулировки могут не найти страницу. Запрос к поиску формулирует модель, поэтому на слабой модели поиск хуже.
5. **Страницы-картинки.** 92 страницы распознаны Tesseract, в таблицах возможны ошибки распознавания. Подсветка цитаты на них не работает.
6. **Порядок затяжки на рисунке.** Заказчик просил давать его словами. Если порядок есть только на картинке, агент должен сказать об этом и дать страницу.
7. **Время ответа.** На один ход уходит несколько вызовов модели. Смотрим самый долгий ход в отчёте: для видео одним дублем это важно.
8. **Стоимость сценария.** Вход в несколько раз больше выхода: инструкция и описания инструментов повторяются в каждом вызове. Смотрим, сколько читается из кэша.
9. **Подача для новичка.** Проверяется только с настоящей моделью: ответ новичку должен быть подробнее, чем опытному.
10. **Выбор инструмента по разговорной фразе.** Сценарий F5: механик говорит «глянь последнюю запись», агент должен запросить диагностику.
11. **Голосовой ввод на телефоне.** Проверяется вручную на стенде с HTTPS.

## Как заполнить шаблон расчёта

В шаблоне организатора строка на каждый шаг агента, который вызывает модель. У нас таких шагов четыре, столько же строк в шаблоне:

| Строка шаблона | Наш шаг в отчёте |
|---|---|
| 1 | Выбор инструмента и поиск |
| 2 | Генерация ответа |
| 3 | Формирование заявки |
| 4 | Повтор после проверки ссылок |

Для каждой строки из раздела отчёта «Для шаблона расчёта стоимости» берутся: модель, вызовов на сценарий, токенов на входе и на выходе за вызов. Цены и валюта берутся с сайта поставщика на день расчёта. Через ProxyAPI цены в рублях, курс доллара не нужен.

В три строки комментария:

1. Допущения: один запрос равен сценарию от получения результата диагностики до ответа механику или заявки. Пересчёт на парк: 50 машин, проверка раз в две недели, два-три вопроса на проверку. Индексация руководств бесплатна: поиск работает без модели и эмбеддингов.
2. Ссылка на прайс и на отчёт с замерами. Что может изменить цифры: доля чтения из кэша, длина истории чата, число повторов после проверки ссылок.
3. Варианты без внешней модели: российское облако и локальная модель на сервере заказчика с ценой токенов 0 и затратами на сервер. Сравнение качества и стоимости вариантов: `docs/model-comparison.md`.

## Когда считаем готовым

- Ошибок в правилах нет.
- Контрольные вопросы: не меньше 18 из 21, все три отказа и случай с расхождением документов пройдены.
- Сценарий С1 проходит целиком до номера заявки.
- Самый долгий ход укладывается во время, приемлемое для видео одним дублем. Ожидание ответа модели в видео можно ускорять, но не вырезать.

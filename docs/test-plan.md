# План прогона на настоящей модели

Продукт собран и проверен на заглушке модели. Этот документ описывает, что осталось проверить на настоящей модели, какими командами и на что смотреть в отчётах. Цель прогона: найти слабые места до сдачи, а не подтвердить, что всё хорошо.

## Что уже проверено без модели

| Что | Как проверено | Итог |
|---|---|---|
| Правила кода | 50 автотестов | проходят |
| Сценарии защиты и контрольные случаи | `eval.run_scenarios` на заглушке | правила: 46 из 46 |
| Поиск нужной страницы по вопросу | `eval.run_eval search` | 18 из 18 |
| Запуск из чистой копии репозитория | клон, сборка, индексация, запрос | сборка и запуск 73 с при готовом кэше Docker, индексация 128 с |
| Пустая база знаний | запуск без PDF | интерфейс и ответы прямо говорят, что руководства не загружены |
| Слой локальной модели | Qwen2.5 7B через Ollama | работает, качество 14 из 21 |

Чего прогон на заглушке не показывает: качество текста ответов, выбор инструмента по смыслу фразы, языки, подачу для новичка, стоимость и время.

## Шаги

1. Вписать в `.env` ключ и адрес. Для ProxyAPI:

```bash
LLM_PROVIDER=anthropic
ANTHROPIC_BASE_URL=https://api.proxyapi.ru
ANTHROPIC_API_KEY=ключ_ProxyAPI
LLM_MODEL=anthropic/claude-opus-5-5
PRICE_CURRENCY=RUB
PRICE_INPUT_PER_MTOK=цена_ввода_с_сайта
PRICE_OUTPUT_PER_MTOK=цена_вывода_с_сайта
PRICE_CACHE_READ_PER_MTOK=цена_чтения_кэша_с_сайта
```

2. Перезапустить сервер:

```bash
docker compose up -d --build backend
```

3. Проверить ключ и то, какие возможности принимает шлюз. Скрипт сам подскажет, что выключить в `.env`:

```bash
docker compose exec backend uv run --no-dev python -m eval.preflight
```

4. Прогнать сценарии. Отчёт сохраняется в `data/eval`:

```bash
docker compose exec backend uv run --no-dev python -m eval.run_scenarios
```

5. Прогнать 21 контрольный вопрос:

```bash
docker compose exec backend uv run --no-dev python -m eval.run_eval ask
```

6. Для сравнения с другой моделью поменять настройки модели в `.env` и повторить шаги 2–5. Результаты внести в [model-comparison.md](model-comparison.md).

Прогон очищает чат по машинам из сценариев и создаёт одну заявку в заглушке ТОиР. Ключ `--no-ticket` у прогона сценариев отключает отправку заявки.

## Как читать отчёт сценариев

- **Ошибки в правилах.** Их быть не должно при любой модели. Каждая такая строка означает ошибку в коде, чинить до сдачи.
- **Слабые места модели.** Это список для доработки инструкции агента и поиска. Если пункт не лечится инструкцией, он попадает в честный раздел «Что не сделано».
- **Расход по сценариям и таблица для шаблона.** Из них заполняется расчёт стоимости.

## Где мы ждём слабые места

Это предположения, прогон должен их подтвердить или снять.

1. **Слой Claude ни разу не запускался.** Первый запрос может упасть на параметре, который шлюз не принимает. Для этого сделаны предполётная проверка и выключатели в `.env`.
2. **Дословность цитат.** Если модель пересказывает страницу вместо копирования, код отбросит пункт и механик увидит «подтвердить не удалось». Признак: много отказов на вопросах, где ответ в руководстве есть.
3. **Не то число с правильной страницы.** Код проверяет, что число стоит на странице, но не что оно отвечает на вопрос. На слабой модели это случалось. Признак: в прогоне вопросов «нет ожидаемых чисел» при верной странице.
4. **Поиск только по словам.** Синонимы и разговорные формулировки могут не найти страницу. Запрос к поиску формулирует модель, поэтому на слабой модели поиск хуже.
5. **Страницы-картинки.** 92 страницы распознаны Tesseract, в таблицах возможны ошибки распознавания. Подсветка цитаты на них не работает.
6. **Порядок затяжки на рисунке.** Заказчик просил давать его словами. Если порядок есть только на картинке, агент должен сказать об этом и дать страницу.
7. **Время ответа.** На один ход уходит несколько вызовов модели. Смотрим самый долгий ход в отчёте: для видео одним дублем это важно.
8. **Стоимость сценария.** Вход в несколько раз больше выхода: инструкция и описания инструментов повторяются в каждом вызове. Смотрим, сколько читается из кэша.
9. **Языки и подача для новичка.** Проверяются только с настоящей моделью. Таджикский автоматически не проверяется: у него та же кириллица, смотреть глазами.
10. **Выбор инструмента по разговорной фразе.** Сценарий F5: механик говорит «глянь последнюю запись», агент должен запросить диагностику.
11. **Голосовой ввод на телефоне.** Проверяется вручную на стенде с HTTPS.

## Как заполнить шаблон расчёта

В шаблоне организатора строка на каждый шаг агента, который вызывает модель. У нас таких шагов четыре, столько же строк в шаблоне:

| Строка шаблона | Наш шаг в отчёте |
|---|---|
| 1 | Выбор инструмента и поиск |
| 2 | Генерация ответа |
| 3 | Формирование заявки |
| 4 | Повтор после проверки ссылок |

Для каждой строки из раздела отчёта «Для шаблона расчёта стоимости» берутся: модель, вызовов на сценарий, токенов на входе и на выходе за вызов. Цены и валюта берутся с сайта поставщика на день расчёта. Через ProxyAPI цены в рублях, курс доллара не нужен.

В три строки комментария:

1. Допущения: один запрос равен сценарию от получения результата диагностики до ответа механику или заявки. Пересчёт на парк: 50 машин, проверка раз в две недели, два-три вопроса на проверку. Индексация руководств бесплатна: поиск работает без модели и эмбеддингов.
2. Ссылка на прайс и на отчёт с замерами. Что может изменить цифры: доля чтения из кэша, длина истории чата, число повторов после проверки ссылок.
3. Варианты без внешней модели: российское облако и локальная модель на сервере заказчика с ценой токенов 0 и затратами на сервер. Сравнение качества и стоимости вариантов: `docs/model-comparison.md`.

## Когда считаем готовым

- Ошибок в правилах нет.
- Контрольные вопросы: не меньше 18 из 21, все три отказа и случай с расхождением документов пройдены.
- Сценарий С1 проходит целиком до номера заявки.
- Самый долгий ход укладывается во время, приемлемое для видео одним дублем. Ожидание ответа модели в видео можно ускорять, но не вырезать.

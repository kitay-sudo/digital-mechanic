# Проект решения

Что за продукт, для кого он сделан и почему устроен именно так. Как запустить и проверить: [README](../README.md).

## 1. Задача

Механик автопарка получает от ML-сервиса «НейроДВС» результат акустической проверки двигателя: статус, тип неисправности, оценку отклонения, уверенность и качество записи. Сам по себе этот результат механику мало что говорит. Нужен помощник, который:

1. получит результат проверки от внешнего ML-сервиса;
2. объяснит отклонение, возможные причины и риски простыми словами;
3. найдёт в руководствах на этот двигатель процедуры, нормативы и рекомендации;
4. ответит на уточняющие вопросы с документом и страницей;
5. по подтверждению механика сформирует заявку на дефектовку для ТОиР.

Парк: 50 машин, четыре семейства двигателей (ЯМЗ-236М2, ЯМЗ-536, ЗМЗ-5234.10, ЗМЗ-40904.10 и ЗМЗ-40905.10), шесть руководств в PDF, часть страниц только картинками. Ссылка всегда идёт на номер страницы PDF, а не на номер, напечатанный в книге.

## 2. Пользователь

| Кто | Какой он | Что ему нужно |
|:---|:---|:---|
| Механик | руки в масле, часто старше 50 лет или новичок после техникума, работает с телефона в цеху | понять вердикт за секунды, получить шаги по порядку, не печатать |
| Главный механик | отвечает за парк и выпуск машин в рейс | видеть, какие машины требуют внимания и как меняется их состояние |
| Администратор | ведёт механиков, руководства и подключения | видеть, что спрашивали и где агент не нашёл ответа, и исправлять это без программиста |

## 3. Принципы

- **Только руководство этого двигателя.** Нормативы, допуски и порядок работ агент берёт только из документов двигателя выбранной машины. Чужой документ ему недоступен.
- **Модель предлагает, код проверяет.** Каждая ссылка несёт дословную цитату, код сверяет её со страницей PDF. Число из руководства должно стоять на процитированной странице. Что не подтвердилось, механик не увидит.
- **Честный отказ лучше догадки.** Если в руководстве ответа нет, агент так и говорит и советует дефектовку.
- **Решает механик.** Заявка уходит только после его подтверждения показанного состава. Приоритет агент только предлагает и объясняет.
- **Ничего лишнего.** Две главные кнопки, вердикт сверху, шаги по одному, голос вместо клавиатуры.

## 4. Дизайн

Интерфейс сдержанный и инженерный, как чертёж: он должен читаться в цеху с телефона и не отвлекать.

- **Цвет только по делу.** Графитовая тёмная тема и светлая. Цветом выделен только статус: норма зелёным, внимание жёлтым, опасность красным.
- **Чертёж как фон.** Тонкие линии двигателя на экране входа, в пустом чате и в обучении. Шрифт IBM Plex, цифры моноширинные.
- **Крупно и по порядку.** Вердикт сразу под заголовком, шаги проверки пронумерованы и отмечаются как сделанные, кнопки под палец.
- **Панели снизу.** Все панели и подтверждения выезжают снизу, без всплывающих окон, теней и скруглений.
- **Списки таблицами.** История проверок, заявки, журнал и механики показаны таблицами на отдельных экранах с возвратом в чат.

Статичный макет интерфейса, сделанный до спринта: [mockups/digital-mechanic.html](mockups/digital-mechanic.html).

## 5. Путь механика

1. Входит в одно касание: фамилия в списке и PIN.
2. Видит парк: машины, которые требуют внимания, стоят выше.
3. Открывает машину и нажимает «Получить результат диагностики». Агент сам запрашивает результат, смотрит историю машины и ищет в руководствах.
4. Читает вердикт и шаги проверки со ссылками. Ссылка открывает страницу PDF, цитата выделена.
5. Задаёт вопросы голосом или текстом, может приложить фото узла.
6. Нажимает «Создать заявку», проверяет состав и подтверждает. Получает номер заявки.

| Результат проверки | Что делает агент | Заявка |
|:---|:---|:---|
| Норма | коротко сообщает и сравнивает с прошлыми проверками | не предлагается |
| Отклонение | объясняет риск, даёт проверки и ремонт со страницами, предлагает приоритет | можно оформить |
| Отклонение, но инструкции в руководстве нет | говорит об этом, советует дефектовку, чужие нормативы не берёт | не отправляется, есть текст рекомендации |
| Запись с помехами | предупреждает первой строкой, выводы осторожные | только после согласия механика |
| Уверенность ниже 0,50 | советует повторную проверку | не оформляется |
| Сбой записи или плохое качество | диагноз не ставит, просит повторить запись | нет |
| Тип неисправности невозможен для двигателя | считает это ошибкой модели диагностики, а не диагнозом | нет |

## 6. Архитектура

```text
vehicles.json, API учётной системы  ->  Парк и история машины
ML-сервис «НейроДВС»  <-  get_diagnosis  <-  Агент  ->  ответ со ссылками  ->  Интерфейс
6 PDF  ->  страницы и распознавание  ->  Индекс FTS5  <-  search_manuals, read_manual_page
                                                        Агент  ->  черновик заявки  ->  подтверждение  ->  ТОиР
Журнал: вопросы, ответы, страницы, шаги агента, токены, стоимость, время
```

| Часть | Что делает | Код |
|:---|:---|:---|
| Интерфейс | парк, чат, страница руководства, экраны администратора | `frontend/` |
| Сервер | чат потоком событий, журнал, вход и роли, API для внешних систем | `backend/app/` |
| Агент | цикл модели с инструментами, проверка ответа | `backend/app/agent/` |
| База знаний | текст по страницам, распознавание сканов Tesseract, поиск SQLite FTS5 с русским стеммером | `backend/app/kb/` |
| Слой модели | Claude по API, локальная модель с форматом OpenAI, Yandex AI Studio, заглушка | `backend/app/agent/llm.py` |
| MCP-коннектор | инструменты агента для внешних ИИ-ассистентов | `mcp-server/` |

Поиск по словам, без эмбеддингов: индексация бесплатна и быстра, а запросы к поиску формулирует модель. Обозначения деталей, моменты затяжки и номера пунктов по словам находятся точнее.

## 7. Агент

| Инструмент | Что делает |
|:---|:---|
| `get_diagnosis` | результат проверки от ML-сервиса по машине и номеру проверки |
| `get_vehicle_history` | карточка машины, прошлые проверки и заявки |
| `search_manuals` | поиск только по руководствам двигателя машины |
| `read_manual_page` | страница PDF целиком: таблицы и соседний контекст |
| `prepare_ticket` | черновик заявки из проверенных ссылок |
| `submit_ticket` | отправка в ТОиР после подтверждения механика |

Кнопки интерфейса отправляют обычный текст, агент сам решает, какой инструмент вызвать и что делать с результатом. Коды F01-F14 в руководствах не встречаются, поэтому агент ищет по названию узла и признакам из ответа ML.

Память по машине: прошлые проверки, заявки и отметки шагов. Если тот же тип неисправности уже ремонтировали, код предупреждает «Повтор после ремонта». Если машину продолжает другой механик или прошло больше шести часов, агент начинает с того, на чём остановились.

## 8. Приоритет заявки

Таблицы приоритетов у заказчика нет, логика своя и показана механику:

1. У каждого типа неисправности базовая критичность. Высокая у узлов, отказ которых делает машину неготовой к рейсу: тормоза, коробка передач.
2. Поправка не больше одной ступени по оценке отклонения и её росту от проверки к проверке.
3. При помехах или уверенности ниже 0,60 приоритет не выше среднего.
4. Механик видит основание одной строкой и может изменить приоритет: окончательный выбор за ним.

| Приоритет | Что делать |
|:---|:---|
| высокий | на дефектовку до выпуска в рейс |
| средний | дефектовка на ближайшее ТО, работа под наблюдением |
| низкий | машина работает, узел проверяется на следующей проверке |

## 9. Заявка в ТОиР

Состав по контракту заглушки ТОиР: машина, проверка, тип неисправности из ответа ML, заключение, приоритет, перечень работ (не пустой), запчасти из руководства (может быть пустым), ссылки на документ и страницу PDF (не пустые). Заглушка смысл заявки не проверяет, поэтому код проверяет сам: тип совпадает с результатом проверки, при норме и сбое заявки нет, каждая ссылка подтверждена цитатой. Номера заявок продукт хранит у себя: заглушка их не хранит.

## 10. Данные и безопасность

- **Материалы заказчика вне Git.** PDF руководств и данные заглушек скачиваются при развёртывании по ссылке из `MATERIALS_URL`.
- **Ключи только в `.env`.** В репозитории лишь шаблон `.env.example`.
- **Данные диагностики не команды.** Посторонние указания в описании признаков отбрасываются до модели и до экрана, администратор видит такой случай в журнале.
- **Роли.** Механик видит парк, чат и руководства; журнал, механики и подключения открыты только администратору.
- **Три уровня закрытости.** Зарубежная модель через шлюз, российское облако Yandex AI Studio или локальная модель на сервере заказчика: [local-model.md](local-model.md), [model-comparison.md](model-comparison.md).

## 11. Развитие для пилота

| Шаг | Зачем |
|:---|:---|
| Переходник к ТОиР на 1С | отправка заявки уже вынесена в сменный приёмник, остаётся один модуль |
| Примечания администратора для агента | закрыть случаи «в руководстве нет» подтверждённым решением без программиста |
| Кэш разбора для пары «тип неисправности и двигатель» | 56 пар на весь парк, повторный разбор дешевле |
| Смысловой поиск поверх поиска по словам | вопросы своими словами, проверка на контрольном наборе не хуже 21 из 21 |
| Работа при слабой связи | последние ответы и страницы руководства на устройстве, локальная модель на посту |

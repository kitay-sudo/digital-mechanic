# Проверка качества

Как проверяется, что агент отвечает по руководствам и держит правила, и какие результаты получены. Числа взяты из отчётов прогонов в `data/eval`.

## 1. Что проверяется

| Уровень | Инструмент | Что ловит | Нужна модель |
|:---|:---|:---|:---|
| Правила кода | автотесты `backend/tests`, 148 тестов | исходы диагностики, сверка цитат и чисел, допуск заявки, роли | нет |
| MCP-коннектор | автотесты `mcp-server/tests`, 10 тестов | инструменты, ключи, суточный лимит | нет |
| Набор вопросов | `eval.run_eval data` | ожидаемые числа есть на указанных страницах | нет |
| Поиск | `eval.run_eval search` | нужная страница попадает в выдачу по тексту вопроса | нет |
| Стенд | `eval.smoke` | страницы, подключения, вход, коды ошибок, время ответа | нет |
| Ответы агента | `eval.run_eval ask` | страница, числа, отказ вне базы, показ расхождения | да |
| Сценарии защиты | `eval.run_scenarios` | С1-С4 и контрольные случаи: правила кода и качество ответа | да |
| Ключ и шлюз | `eval.preflight` | какие возможности слоя модели принимает ключ | да |

Контрольный набор: 21 вопрос по шести руководствам, по четыре на двигатель, случай с расхождением документов и три вопроса, на которые агент должен отказать. В файле [questions.json](../backend/eval/questions.json) нет текста руководств: только вопрос, документ, страница и ожидаемые числа.

## 3. Как прогнать

Команды выполняются из корня репозитория при запущенном `docker compose up -d`. Для проверок с моделью в `.env` нужен ключ модели, для работы скриптов при включённом входе ещё `INTEGRATION_API_KEY`: один из ключей `INTEGRATION_API_KEYS`.

Проверить ключ и возможности шлюза.
```bash
docker compose exec backend uv run --no-dev python -m eval.preflight
```

Прогнать контрольные вопросы.
```bash
docker compose exec backend uv run --no-dev python -m eval.run_eval ask
```

Прогнать сценарии защиты, отчёт сохраняется в `data/eval`.
```bash
docker compose exec backend uv run --no-dev python -m eval.run_scenarios
```

| Опция | Что делает |
|:---|:---|
| `--only С1,КС4` | только перечисленные сценарии |
| `--no-ticket` | без отправки заявки в ТОиР |

Прогон очищает чат по машинам из сценариев и создаёт одну заявку в заглушке ТОиР.

## 4. Как читать отчёт сценариев

- **Ошибки в правилах.** Их не должно быть при любой модели: каждая такая строка означает ошибку в коде.
- **Слабые места модели.** Список для доработки инструкции агента и поиска.
- **Расход.** Токены и стоимость по шагам агента: из них заполняется расчёт стоимости.

## 5. Порог приёмки модели

Одинаковый для всех моделей:

1. Ошибок в правилах кода нет.
2. Контрольные вопросы: не меньше 18 из 21, все три отказа и случай с расхождением документов пройдены.
3. Сценарий С1 проходит целиком до номера заявки.

## 6. Известные слабые места

1. **Не то число с правильной страницы.** Код проверяет, что число стоит на процитированной странице, но не что оно отвечает на вопрос. Это ловят контрольный набор и механик по цитате рядом с шагом.
2. **Поиск по словам.** Разговорные формулировки и синонимы могут не найти страницу. Запрос к поиску формулирует модель, поэтому слабая модель ошибается здесь чаще.
3. **Страницы-сканы.** 92 страницы распознаны Tesseract, в таблицах возможны ошибки распознавания, подсветка цитаты на них не работает.
4. **Порядок затяжки на рисунке.** Если порядок есть только на картинке, агент говорит об этом и даёт страницу.
5. **Наш набор вопросов.** Он составлен по страницам, которые мы нашли сами. Вопросы экспертов могут оказаться труднее.
